==================================================
13. RECONCILIATION RULES
==================================================

Use:

CustomerId + NormalizedHostname

as the primary server matching rule.

Never match only by hostname without CustomerId.

Classification:

CREATE
No matching server exists.

UPDATE
Matching server exists and one or more supported canonical discovery fields would change.

UNCHANGED
Matching server exists and relevant fields contain no meaningful changes.

WARNING
Row can potentially import but contains data requiring user attention.

REJECT
Mandatory information is missing or data prevents safe reconciliation.

Do not perform database changes during Preview.

==================================================
16. PREVIEW / COMMIT MODEL
==================================================

Implement a two-stage import process.

STAGE 1:
Upload and Preview

- save batch
- parse
- validate
- stage
- reconcile
- classify
- calculate proposed changes
- return summary

No canonical inventory updates occur.

STAGE 2:
Commit Import

Only after explicit user confirmation:

- Create Create-classification servers
- Apply approved Update-classification technical changes
- Save ServerDiscoverySnapshot records
- update server LastImportedAt
- update server LastImportBatchId
- create audit events
- mark import completed

Unchanged rows should still be represented in import history.

Reject rows must never update canonical inventory.

==================================================
17. IDEMPOTENCY
==================================================

Uploading the same file twice must be detectable using file hash.

Do not automatically block it, because users may intentionally rerun a discovery file.

Show a warning such as:

This file appears to have been imported previously on <date>.

If the same file is imported again and nothing has changed:
records should classify as Unchanged.

==================================================
18. CONCURRENCY / SAFETY
==================================================

Do not allow a batch already committed to be committed a second time.

Do not allow a Failed or Cancelled batch to modify inventory.

Use a database transaction for the Commit operation.

If commit fails:
rollback the canonical inventory changes.

Set the ImportBatch status appropriately.
